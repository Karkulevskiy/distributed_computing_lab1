# Задание 3
### Read-heavy сценарий:
- Стандартный pthread_rwlock_t показывает стабильное увеличение производительности с ростом потоков до 8 и плавное падение дальше.
- Кастомная реализация работает почти одинаково на 1-2 потоках, но значительно теряет производительность при увеличении числа потоков (особенно при 8+ потоках), из-за блокировки всех новых read при присутствии write.

### Balanced сценарий:
- Производительность обеих реализаций падает с увеличением числа потоков, так как количество операций записи существенно больше и возникает конкуренция.
- Пользовательский rwlock демонстрирует большее падение при больших потоках.
<img width="713" height="547" alt="2" src="https://github.com/user-attachments/assets/45772544-7b44-4a7a-85b5-c9d78ce6306b" />

### Write-heavy сценарий:
- Производительность сильно ограничена количеством write.
- Кастомная реализация хуже стандартной, особенно при 16 и 32 потоках.
<img width="713" height="547" alt="3" src="https://github.com/user-attachments/assets/91510825-bb77-4263-ad8a-27bfaf4c44c0" />

## Вывод по производительности
- На низком числе потоков (1-2) кастомная реализация сравнима со стандартной.
- При высоком числе потоков (>8) стандартный pthread_rwlock_t значительно эффективнее.
- Используемая политика приоритета write блокирует новых read, создавая узкое место при большом количестве потоков.
- Возможны расходы на частое пробуждение потоков через pthread_cond_signal/broadcast.
